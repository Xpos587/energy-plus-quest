# Передача спецпроекта на площадку

## Что передаём

Файл `release/energy-plus-quest-static.zip` — автономный статический спецпроект
без PHP, WordPress, Node.js и backend-зависимостей.

После распаковки в целевой папке должны находиться:

```text
index.html
assets/
brand/
fonts/
```

Нельзя загружать дополнительную внешнюю папку `dist/`: `index.html` должен быть
непосредственно в корне URL спецпроекта.

## Требования к серверу

- отдавать статические файлы по HTTPS;
- не переписывать относительные пути к ресурсам;
- отдавать корректные MIME-типы для `.js`, `.css`, `.webp`, `.png` и `.woff2`;
- для прямых внутренних URL возвращать `index.html`, если позднее в игре
  появится клиентская маршрутизация;
- не внедрять WordPress-разметку, плагины или глобальные CSS внутрь страницы
  спецпроекта.

Рекомендуемое кеширование:

- `index.html`: `Cache-Control: no-cache` или короткий TTL;
- `assets/*`: `Cache-Control: public, max-age=31536000, immutable`;
- `fonts/*` и `brand/*`: длительный кеш с перевалидацией.

## Проверка после размещения

1. Открыть точный URL спецпроекта в новой вкладке.
2. Убедиться, что нет ошибок `404` для JS, CSS, изображений и шрифтов.
3. Пройти сцену до экрана «Первый участок пройден».
4. Проверить desktop при масштабе браузера `100%`, `125%` и `140%`.
5. Проверить мобильный экран и планшет в портретной ориентации.
6. Убедиться, что страница не получает горизонтальный скролл.

## Что ещё нужно согласовать

- точный production-URL;
- пункт меню или страница основного сайта, откуда открывается игра;
- правила кеширования `index.html`, если они отличаются от рекомендаций;
- система аналитики и события, если заказчику нужны отдельные игровые отчёты.

Хранение результатов, аккаунты, email и обмен данными с WordPress сейчас не
требуются. Если это изменится, интеграцию нужно описать отдельно до разработки.
