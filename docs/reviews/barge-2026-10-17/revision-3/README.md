# Баржа · раунд 3

[Единый PDF, 28 страниц — следующая итерация и критический разбор](barge-round-3-2026-10-18.pdf). [Полный собственный разбор с источниками](critique.md).

Это самостоятельная проверка по зафиксированным критериям, **не согласование Феди** и не пользовательский тест. А/Б/В остаются отдельными прототипами; код и медиапайплайн игры этим пакетом не изменены. Предыдущие PDF и источники R2 сохранены.

## Что изменилось после критики R2

- Первый вход показывает полную каноническую задачу; на малой высоте все три абзаца сгруппированы в две части, без отдельной почти пустой страницы. Возврат вводную повторно не навязывает.
- До решения нет предвыбранного remote; закрытие вводной под неподвижным курсором не создаёт случайный акцент. Preview не пересоздаёт нажатую кнопку, первый клик не теряется. На 320 px постоянно виден прежний факт о своей погрузке Петра.
- Имена связаны с людьми без новых формулировок. Номера 2/3 находятся в одной парной метке одного ближнего крана и не закрывают друг друга.
- Вместо повторов старого результата — новые четыре исхода для каждого подарка: пульт/пустая кабина, усталость/высокая лестница, подарок на причале/судно без него, огорчённый Пётр/его ожидающий груз.
- Малый подарок показан дополнительным близким ракурсом палубы или причала, а не гигантской коробкой. Ошибочный camera edit с подарком в двух местах забракован и исправлен.
- В выборе лодки и предварительном ожидании теперь сама лодка, не нейтральный ящик.
- Remote показан целиком на 390×844, 844×390, 1440×900. На 320×568 — две части с прежним текстом и прежним шрифтом. Пётр всегда целиком.

## Проверки и пределы

- `check.mjs`: 180 состояний, 0 переполнений; четыре окна, три подарка, три варианта, выбор и четыре результата. Изображения декодированы и шрифты загружены до снимков. [geometry.json](geometry.json).
- `verify.mjs`: 36 первых входов, 144 клавиатурных и 144 первых выбора мышью/возврата, 144 точных совпадения полного текста результатов с источником. [interaction-checks.json](interaction-checks.json).
- `dpr-probe.mjs`: фактический `currentSrc`, полезные пиксели кадра и показ при DPR1/2. [dpr.json](dpr.json). Кадр 768×512 покрывает проверенный мобильный показ, но **не desktop DPR2**. Это композиционные пробы, не финальные high-DPI-мастера.
- `touch.mjs`: 24 первых тапа и возврата в эмуляции touch/DPR2 на 320×568 и 390×844, все три варианта. [touch-checks.json](touch-checks.json).
- Окна: 320×568, 390×844, 844×390, 1440×900; Chromium с эмуляцией размеров, не физический телефон.
- `report.mjs` создаёт PDF; страницы отрендерены через pdftoppm и визуально осмотрены. Размеры/хеши review-файлов не вычислялись.

А хуже различает лица в малом общем виде; Б рекомендован для следующей проверки с человеком; В переработан для touch: постоянно показаны подарок, кран и баржа; нужно проверить считывание одного места, а не дополнительных кранов. Не закрыты предметная необходимость крана для носков/камеры, термин «офис / ПРУ», узнаваемость упаковки малого подарка на общем плане и финальная детализация. Человеческой приёмки нет.

## Интерактивно

Открыть `prototype.html?v=a|b|c&parcel=boat|camera|socks` из этой папки. Без параметра state показана вводная. `state=` открывает нейтральный выбор после вводной; `state=remote|rush|wait|petr` — конкретный результат. `active=...` задаёт только состояние визуального фокуса для сравнения.

Фокус/наведение показывает способ работы; Enter/клик на кнопку сразу открывает результат. «О задаче» доступно у заголовка, отдельного confirm нет. «Продолжить» в этом прототипе возвращает к сравнению, а не запускает последнюю милю. Не выдавать эту демонстрационную навигацию за проверку живой игры.
