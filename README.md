# Energy+ Quest

Браузерная игра-квест «Доставляем радость» для площадки «Энергия+».

## Что делаем сейчас

Актуальный статус и незаконченные задачи: [передача проекта](docs/plans/handoffs/2026-10-23-transfer.md).
В Git хранятся код, текстовые документы и манифест медиа. Изображения, видео,
шрифты и последний PDF восстанавливаются из текущего GitHub Release с проверкой
SHA-256; сборки и мастер-файлы не раздувают историю. Правила — в
[политике хранения](docs/REPOSITORY-HYGIENE.md).

Текущий frontend включает:

- онбординг с выбором профиля, получателя и посылки;
- интерактивную карту с четырьмя вариантами перевозки;
- последствия решений и три показателя игрока;
- сравнение ручного выбора с Express;
- mobile и desktop;
- статическую production-сборку без backend.

Техническая команда площадки подтвердила формат автономного статического
HTML/CSS/JS-архива. Первый архив они разместят на тестовом окружении как
отдельный спецпроект; backend и интеграция с WordPress сейчас не нужны.

## Запуск

```bash
bun install
bun run media:hydrate
bun run dev
```

Полная локальная проверка:

```bash
go-task verify
bun run test:e2e
```

Архив для площадки заказчика автоматически обновляется при `bun run build`
и `bun run deploy`: оптимизация выполняется один раз, затем эта же сборка
упаковывается и проверяется через Nginx. Если проверка не проходит, команда
останавливается до публикации, а предыдущий готовый архив сохраняется.
В `dist/` и ZIP попадает один и тот же отобранный набор: код, используемые
изображения всех вариантов, адаптивные форматы, видео, шрифты и лицензии.
Старые иллюстрации, исходники заменённых картинок и материалы для согласования
не копируются целыми папками. Оригиналы остаются в проекте.

Подготовить только архив без публикации сайта и изменения `dist/`:

```bash
bun run package
```

Нужны Bun, Podman, zip, unzip и curl. Предыдущий успешный архив сохраняется
рядом как `energy-plus-quest-static.previous.zip`.

Результат: `release/energy-plus-quest-static.zip`. `index.html` находится в
корне архива, а относительные пути проверяются из вложенной папки спецпроекта.
Проверка запуска и прохождения в браузере выполняется отдельно;
порядок передачи описан в [инструкции для площадки](public/README-DEPLOY.txt).

Целевой URL площадки: `https://e-plus.media/specprojects/joydelivery/`.

## Обновление сайта в Dokploy

```bash
bun run deploy
```

Альтернатива: `go-task deploy`. Команда собирает текущие локальные файлы,
включая незакоммиченные правки, отправляет сборку и `Containerfile` по SSH,
запускает Dokploy, ждёт завершения и сравнивает опубликованные HTML, JS и CSS со
сборкой. Адрес: <https://energy-plus-quest.hypcat.net/>.

Приложение использует источник **Drop** с доставкой по SSH: ZIP API этой
установки отклоняет большой архив с ошибкой 413. Автодеплой из Git отключён,
чтобы Git не заменил локальную сборку. Git-коммит и push для обновления не нужны.

Проверка без публикации: `bun run deploy --dry-run`.
Нужны Bun, `ssh`, `rsync` на локальной машине и сервере, доступ по SSH-алиасу
`infra-admin` и API-ключ Dokploy. Для ускорения передаются только изменившиеся
данные; полный набор файлов новой сборки проверяется в отдельной папке на сервере.
Алиас можно переопределить через `DOKPLOY_SSH_HOST`.
Ключ читается из `DOKPLOY_API_KEY` либо
из строки `DOKPLOY_API_KEY=...` в `/home/michael/Github/infra/secrets.local.md`.
Другой файл можно задать через `DOKPLOY_SECRETS_FILE`.
На сервер отправляются только `dist/` и `Containerfile`.
Материалы из `dist/review/` включаются только для папок, на которые ссылаются
собранные JS/CSS; остальные презентации и старые скриншоты не отправляются.
Последний результат и предыдущие настройки источника сохраняются в игнорируемой
папке `.tmp-work/`. При ошибке развёртывания нужно
посмотреть журнал в Dokploy перед повторным запуском; автоматического отката нет.
Предыдущая сборка сохраняется на сервере рядом с `code/` в папке `code-before-*`.
Эти резервные папки не удаляются автоматически.
