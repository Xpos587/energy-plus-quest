Энергия+ — «Доставляем радость»
Передача статической игры на площадку

ЧТО В АРХИВЕ

Игра включает подготовку отправления и пять этапов: перевозчик, погрузка
на фуру, склад, погрузка на баржу и последняя миля. Для работы достаточно
статического HTTPS-сервера; Node.js, PHP, база данных и API не нужны.

Целевой адрес:
https://e-plus.media/specprojects/joydelivery/

В корне распакованного архива находятся index.html, README-DEPLOY.txt,
nginx-joydelivery.conf, каталоги assets/, brand/, fonts/ и каталоги
иллюстраций и видео, используемых игрой. Если сборка создала quest-cache.js,
он также включён в архив. Передавайте все файлы вместе, сохраняя структуру.
Не добавляйте промежуточную папку dist/.

ПУБЛИКАЦИЯ

1. Сохраните предыдущую опубликованную версию для отката. Подготовьте новую
   версию отдельно, чтобы посетитель не получил смесь старых и новых файлов.
2. Распакуйте содержимое архива в каталог спецпроекта. Например, при webroot
   /srv/www/e-plus.media файл должен оказаться здесь:
   /srv/www/e-plus.media/specprojects/joydelivery/index.html
3. Возьмите прилагаемый nginx-joydelivery.conf. Замените /path/to/webroot
   на фактический webroot, содержащий specprojects/, например
   /srv/www/e-plus.media. Это НЕ каталог самой игры joydelivery/.
4. Подключите этот файл внутри существующего server-блока сайта Nginx либо
   перенесите в него location-блоки из файла. Это фрагмент конфигурации,
   а не самостоятельный nginx.conf. Проверьте совместимость с уже имеющимися
   location-блоками, правилами доступа, CSP, прокси и CDN.
5. Выполните nginx -t. После успешной проверки и согласованного переключения
   версии примените конфигурацию штатной процедурой перезагрузки Nginx.
6. Откройте точный целевой HTTPS-адрес и выполните проверки ниже.

Прилагаемый фрагмент использует файлы на диске через root, по модели примера
RS. Если площадка раздаёт файлы через объектное хранилище или прокси, не заменяйте
её схему локальным root без адаптации: направьте весь /specprojects/joydelivery/
на один источник статических файлов и загрузите туда также JS. Отсутствующий
JS должен возвращать 404, без передачи запроса WordPress. В публичных ответах
HTML и CSS наблюдались заголовки x-amz-*, но сами по себе они не подтверждают
устройство инфраструктуры площадки.

ПУТИ И ВСТРАИВАНИЕ

В сборке используются относительные пути (base './'). Адрес каталога игры
должен заканчиваться символом /: иначе браузер ищет ресурсы уровнем выше.
Прилагаемая конфигурация перенаправляет адрес без завершающего / на адрес с /.

Открывайте игру отдельной страницей. Не вставляйте index.html в шаблон
WordPress и не подключайте к нему стили, оптимизаторы или скрипты сайта.
Не заменяйте отсутствующие JS, CSS и изображения страницей index.html:
отсутствующий файл должен давать HTTP 404, иначе браузер может получить HTML
вместо JavaScript и не запустить игру.

JavaScript поставляется отдельными минифицированными файлами. Минификация
сокращает код; это не обфускация. Не требуется переносить JavaScript внутрь
index.html. Не изменяйте имена файлов или ссылки в готовой сборке.

MIME-ТИПЫ И КЕШИРОВАНИЕ

Прилагаемая конфигурация подключает MIME-типы Nginx и ограничивает правила
каталогом /specprojects/joydelivery/. Проверьте, что JS отдаётся как JavaScript,
CSS — как text/css, а изображения, шрифты и видео — со своими MIME-типами.
Если перед Nginx расположен прокси или CDN, проверьте также его ответы.

index.html и необязательный quest-cache.js требуют повторной проверки сервером
(no-cache). Годовой immutable-кеш разрешён только ресурсам с хешем в имени
из assets/. Остальные ресурсы не должны получать бессрочный immutable-кеш:
их имена могут сохраняться при обновлении содержимого.

ПРОВЕРКА ПЕРЕД ПЕРЕДАЧЕЙ

В репозитории выполните:
sh scripts/package-static.sh

Команда собирает приложение с BUILD_MINIFY=true и BUILD_SINGLEFILE=false,
готовит архив, распаковывает его в проверочное окружение и проверяет HTTP-отдачу
через временный Nginx в Podman. Для этого нужны зависимости проекта, Bun,
Podman и инструменты упаковки, используемые скриптом. Результат успешного
запуска: release/energy-plus-quest-static.zip.

Проверка scripts/verify-static-runtime.mjs проверяет HTTP-ответы, пути,
MIME-типы, доступность ресурсов, перенаправление и 404. Она не проходит игру
в браузере и не подтверждает конфигурацию ещё не проверенного сервера заказчика.

ПРОВЕРКА ПОСЛЕ РАЗМЕЩЕНИЯ

1. Откройте адрес без завершающего /: он должен перенаправить на адрес с /.
2. В новой вкладке откройте игру; проверьте консоль и сеть браузера: не должно
   быть ошибок загрузки, MIME, CSP или выполнения JavaScript. Проверьте именно
   опубликованный адрес, а не только локальный сервер.
3. Пройдите выбор профиля, получателя и подарка, затем все пять этапов.
   Проверьте чтение истории, выбор и изменение решения, результаты,
   возврат с финала и повторное прохождение с самого начала.
4. Перезагрузите страницу в середине игры и проверьте восстановление прогресса.
   Прогресс хранится в браузере на этом адресе. Он не переносится на другие
   устройства или домены и может исчезнуть после очистки данных браузера.
5. Проверьте горизонтальное перемещение панорам мышью и касанием, переключение
   текста кнопками, мобильную ориентацию и рабочий экран презентации.
6. После обновления проверьте как новую вкладку, так и браузер, открывавший
   предыдущую версию: ресурсы и интерфейс должны соответствовать новой сборке.

Не открывайте index.html через file://: используйте HTTP-сервер. Для проверки
именно целевого подпути и Nginx используйте процедуру упаковки выше.

ГРАНИЦЫ ПРОВЕРКИ

Успешная локальная проверка подтверждает работу архива с приложенной
конфигурацией. Она не гарантирует работу при неизвестных правилах сервера,
CDN, CSP или вмешательстве CMS. При проблеме сохраните точный URL, сообщение
консоли, статус, Content-Type и начало ответа не загрузившегося ресурса.
HTML вместо JS часто указывает на перенаправление или подмену ответа сервером;
причину необходимо подтвердить ответами конкретной площадки.

Техническая готовность архива не заменяет согласование сценария, оформления
и разрешение на публикацию. Публикация на сервере заказчика выполняется
ответственными за площадку.
