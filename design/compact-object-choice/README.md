# Автоматизация как игровой ответ

Изолированный интерактивный эскиз: `/design/compact-object-choice/index.html`.
Планшет — временная схема предмета, не финальная иллюстрация. PROD не меняется.

## Решение по сценам

- Перевозчик: рабочее место диспетчера с ноутбуком Express у стоянки. Метка «Платформа Express», тот же поток просмотра и подтверждения, что у машин. Не изображать Express как пятую готовую фуру: по сценарию это способ организации перевозки.
- Укладка: планшет грузчика Compact на рабочей стойке возле фуры. Метка «Система Compact». Это выбор системы размещения вместо самостоятельного выбора места; не подсвечивать рекомендованную зону до подтверждения. Основание: sourceCopy.json p300, p301, p308, p314.
- Склад: существующий терминал WMS — образец предметного выбора.
- Баржа: сохранить существующие предметные/персонажные ответы; отдельный планшет не добавлять без сценарного основания.
- Последняя миля: сохранить транспортные ответы, автоматизированные технологии представлены транспортом.

## Правила

Одинаковые метки и подтверждение для всех ответов. Без звёздочек, «рекомендуем» и обещаний правильного решения. Сценарные результаты и баллы сохраняются. Объект движется вместе со сценой при горизонтальной прокрутке. Не привязывать его к углу экрана как служебную кнопку.

## До переноса в игру

Согласовать предмет и его расположение на укладке; затем нарисовать его в стиле сцены. Для Express подготовить аналогичное рабочее место диспетчера. Проверить оба объекта при мобильной прокрутке и при открытой карточке. Не переносить условный SVG планшета в финальную иллюстрацию без визуального согласования.
